# Tsukada Happy Wedding 💍

結婚式のゲスト向け「写真共有・お祝いメッセージ」Webアプリケーションです。
ゲスト同士で結婚式当日の写真をリアルタイムに共有し、新郎新婦へのお祝いメッセージを送ることができます。

## 🌟 主な機能

- **タイムライン表示**: 投稿された写真、動画、メッセージをリアルタイムで閲覧可能。
- **動画アップロード対応**: MP4, MOV などの一般的な動画形式に対応し、フロントエンド側で自動的にサムネイル画像を抽出して軽量に表示します。
- **幅広いフォーマット対応**: iPhoneの高画質写真(HEIC/HEIF)や、各種動画・音声フォーマットに幅広く対応するMIMEバリデーションを実装。
- **新郎/新婦ゲストフィルター**: ゲストの属性（新郎側・新婦側）に応じたフィルター表示に対応。
- **いいね機能**: 気に入った写真・動画に「いいね」を送信。端末のUUIDを利用し、誰が「いいね」したかを匿名で管理。
- **スライドショー機能**: 会場のスクリーン等で投影するための自動再生スライドショーモードを搭載。
- **一括ダウンロード**: 投稿されたすべてのメディアを1つのZIPファイルとして一括ダウンロード可能。
- **管理画面**: 不適切な投稿の削除機能などを備えた管理者専用画面を用意。

## 🚀 パフォーマンスと負荷対策（アーキテクチャの工夫）

結婚式という特性上、**数十人〜百人規模のゲストが同時に画像をアップロードする**ことが予想されます。
サーバー（特に安価な共有サーバー等）がダウンしないよう、以下のベストプラクティスを取り入れています。

1. **バックグラウンド・ペーシングアップロード**
   - フロントエンドにて、複数枚の画像が選択された場合でも、**1枚ごとに意図的な1秒間のインターバル（ペーシング）**を挟んで非同期で送信します。これにより、サーバーへのスパイクアクセスを防止します。
   - アップロード中もユーザーはモーダルを閉じてタイムラインを閲覧し続けることができます。
2. **画像の先読み（プリロード）**
   - 初回アクセスの名前入力画面（Welcome画面）の裏側で、API通信と最新10件の画像キャッシュ（プリロード）を完了させます。これにより、タイムライン遷移時の待ち時間を「ゼロ」にしています。
3. **高画質サムネイルの自動生成（画像・動画）**
   - **画像**: バックエンドにて自動的に1080pxにスケールダウン＆圧縮（画質90）し、表示の軽量化と高画質を両立。
   - **動画**: `ffmpeg` が使えない共有サーバー環境を考慮し、フロントエンドの `<canvas>` を用いて動画のサムネイルを自動抽出。iOS等のレンダリング遅延対策（シーク＆待機処理）も組み込み、安全・高速にサムネイルを生成します。

- **いいね機能**: 写真・動画・メッセージへのいいね（ダブルタップ対応）、いいね数ランキング
- **大容量動画のチャンクアップロード**: モバイル回線での通信切断に備え、動画ファイルを自動的に分割（チャンク化）し、レジューム＆リトライ機能付きで安定して送信
- **リアルタイム新着通知**: キャッシュ(Etag)とAdaptive Pollingを利用し、サーバー負荷ゼロで新着投稿を検知して画面上部にバッジ表示
- **ベストカメラマン発表機能**: 投稿数をマテリアライズド・キャッシュで即時計算し、披露宴終盤に管理画面からワンタップで「最多投稿者」を発表
- **バックグラウンドアップロード**: 動画などの大容量ファイルでも、進行状況をポップアップで表示しながら裏で安定してアップロード処理を継続

4. **責務の分離（Clean Architecture視点）**
   - **React**: ビジネスロジックを Custom Hooks（`useBackgroundUpload`, `useBatchDownload`）に分離し、Fat Componentを排除。
   - **Laravel**: バリデーションは `FormRequest`、画像処理は `Service` クラスに分離し、Fat Controllerを排除した見通しの良い構造。

## 💻 技術スタック

### Frontend
- **Framework**: React 18 / TypeScript / Vite
- **Styling**: Tailwind CSS
- **Icons**: Lucide React
- **Utils**: JSZip (一括ダウンロード用), FileSaver.js

### Backend
- **Framework**: Laravel 11 / PHP 8.2+
- **Database**: SQLite (開発用) / MySQL (本番環境推奨)
- **Image Processing**: Intervention Image (GD Driver)

## 🛠 セットアップ手順

### 1. リポジトリのクローン
```bash
git clone https://github.com/aqshmodel/wedding.git
cd wedding
```

### 2. バックエンド（Laravel）の構築
```bash
cd backend
composer install

# 環境変数の設定
cp .env.example .env
# .env 内の DB 設定などを適宜変更してください

# アプリケーションキーの生成
php artisan key:generate

# データベースマイグレーション
php artisan migrate

# ストレージのシンボリックリンク作成
php artisan storage:link

# サーバー起動
php artisan serve
```

### 3. フロントエンド（React）の構築
別のターミナルタブを開いて実行します。
```bash
cd frontend
npm install

# 開発用サーバー起動
npm run dev
```

> **Note**: 本番ビルドを行う際は、`frontend/.env.production` を作成し `VITE_API_URL` や `VITE_STORAGE_URL` を本番環境のものに書き換えた上で、`npm run build` を実行してください。

## 📝 開発者向け情報

### コードのフォーマットとLint
フロントエンドは ESLint と TypeScript の strict モードを採用しています。コミット前にエラーが出ないかご確認ください。

### サーバー構成とデプロイのベストプラクティス（共用サーバー向け）
本アプリケーションは、ロリポップ！などの一般的な共用サーバー（SSHアクセス可能な環境）での動作を想定した構成になっています。

デプロイ時は以下のディレクトリ構成と手順を推奨します：

#### 1. 公開ディレクトリの設定
バックエンドの `public/` ディレクトリを、Webサーバーの**ドキュメントルート（公開ディレクトリ）**として設定してください。

#### 2. フロントエンドの統合
React（Vite）でビルドしたフロントエンドのファイル群を、上記のドキュメントルートに統合します。
```bash
# ローカルでフロントエンドをビルド
cd frontend
npm run build

# 生成された dist ディレクトリの中身を、サーバーのバックエンドの public フォルダ内にすべてアップロード（rsync等を使用）
rsync -avz dist/ user@server:path/to/backend/public/
```
これにより、フロントエンドの画面表示（`index.html`）とバックエンドのAPI（`/api/...`）が同一ドメイン内でシームレスに動作します。

#### 3. アップロードディレクトリとシンボリックリンク
画像などのメディアファイルは、セキュリティを考慮し `storage/app/public` に保存されるのがLaravelの基本です。
サーバー上で必ず以下のコマンドを実行し、公開ディレクトリにシンボリックリンクを張ってください。
```bash
cd backend
php artisan storage:link
```
※本アプリではさらに独自に `public/uploads/` ディレクトリを使用する場合があります。デプロイ後、サーバー上の `public/uploads/` ディレクトリに適切な書き込み権限（パーミッション `755` または `777`）が付与与されているか確認してください。サムネイルも `public/uploads/thumbnails/` に生成されます。
